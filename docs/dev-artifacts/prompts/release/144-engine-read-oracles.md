## Items

1. **The name-to-descriptor window of `GetRecord` and cursors.** A read resolves the table by name for authorization and then, after an await, resolves the descriptor again (or opens the cursor), so a rename, drop or re-creation between the two steps authorizes one table and reads another. Find every such window on the single-record read and on cursor creation/fetch (`shamir-server` `engine/db_handler/cursor_handlers/`, `repo_admin/`, `shamir-db` execute/read paths): resolve once, authorize that exact descriptor and read through it; add deterministic tests with a per-instance one-shot pause seam between the two steps (rename or replace the table during the pause; the read must refuse or read the authorized table, never the replacement).
2. **Security audit priority over the read audit.** When a read is denied or refused by a security rule, the security audit entry must be written with priority over (and never lost to) the read-audit path; read the audit emission code of the read surface, prove the current order and any lost or reordered entry, fix it, and pin it with tests that exercise a denial together with a read-audit sink under load.
3. **Oracles for `List(Indexes)`, `GetBufferConfig` and `ListValidators`:** their authorization, visibility (an unreadable table is indistinguishable from a missing one), error codes and output bounds are specified by the guide and the access rules but have no direct tests of the refusal paths: add them (builder-driven, each with a positive control so a missing resource cannot fake a refusal).
