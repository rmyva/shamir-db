# Brief: RESERVED-DB-NAMES (task #2033, release blocker) - database names that collide with the server's own top-level directories are refused everywhere

You are session `rn-1`, a NEW executor in a fresh worktree (`<worktree>`, branch `reserved-db-names`) created from `origin/master`.

## Goal and why
A repository lives at `<data_root>/<db>/<repo>`. The server also owns top-level names in the same `data_root`: the system catalogue file `shamir_db_meta.redb` and the directories `users`, `server_meta`, `cache`, `counters`, `audit`. Today `create_db_as_checked` refuses only the database name `__system__` (`crates/engine/shamir-db/src/shamir_db/shamir_db/db/db_management.rs` about lines 110-120, rename about 295-310). A database called `users` therefore puts its repositories INSIDE the system store's directory: the backup is taken, but the restore REFUSES it (`RESERVED_TOP_LEVEL` in `crates/server/shamir-sync/src/sync/durability/backup/restore/catalogue.rs`, lines 53-60, used at about 181 and 483), so the operator holds a copy that cannot be restored. The store-release barrier also stops inside the found store. After the first release a refusal of a name becomes a breaking change, so the refusal ships now. The owner's decision is made; this is a fix, not a question.
